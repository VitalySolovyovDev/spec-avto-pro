## Technical Implementation Constraints

You must respect the actual build model:

- SEO must be implemented in static source files and build config, not via CMS plugins.
- HTML pages are emitted by `HtmlRspackPlugin` from `frontend/src/index.html` and `frontend/src/privacy.html`.
- The frontend build currently copies `frontend/src/assets/` into `dist/assets/`.
- The site is a static MPA, not a client-side SPA with runtime head management.
- The contact form submits to backend route `POST /api/contact`.
- Production serves static assets and HTML files from the built frontend output.

Important routing constraint:

- the repo explicitly generates `privacy.html`;
- the production backend has a catch-all that falls back to `index.html`;
- a nice URL like `/privacy` is mentioned inside the privacy-policy text, but a matching rewrite rule is not confirmed in the repo.

Because of that, do not assume extensionless public URLs unless they are explicitly supported by code.
